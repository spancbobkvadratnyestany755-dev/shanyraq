# Запуск Shanyraq с настоящими аккаунтами

Код подготовлен, но вход и база НЕ РАБОТАЮТ, пока не выполнены настройки ниже. Демообъявления не переносятся в настоящую базу.

## 1. Создать Supabase

В https://supabase.com/dashboard создайте проект на тарифе Free. Сохраните пароль базы у себя.

Откройте Connect: скопируйте Project URL и Publishable key (начинается с `sb_publishable_`). Они публичные. Вставьте их в `config.js` в поля `supabaseUrl` и `supabasePublishableKey`. Secret key, service_role, пароль базы и Google Client Secret в файлы сайта НЕ вставляются.

Откройте SQL Editor → New query. Вставьте содержимое `schema.sql` и выполните один раз в новом проекте. Скрипт создаёт объявления, хранилище фотографий и правила: посетители читают опубликованное, владелец изменяет только своё. Пока это не настроено и не проверено, сайт нельзя считать готовым к запуску.

## 2. Включить Google

1. В https://console.cloud.google.com создайте проект Shanyraq.
2. В Google Auth Platform настройте Branding и Audience. Для тестирования добавьте свои Google-аккаунты в Test users. В этом режиме вход не доступен всем подряд.
3. Scopes: только `openid`, email и profile. Доступ к письмам Gmail не нужен.
4. Clients → Create client → Web application.
5. Authorized JavaScript origins: адрес сайта; для локальной проверки `http://127.0.0.1:3000`.
6. В Supabase откройте Authentication → Sign In / Providers → Google. Скопируйте оттуда Callback URL.
7. Этот Callback URL вставьте в Google → Authorized redirect URIs.
8. Google Client ID и Client Secret вставьте ТОЛЬКО в настройки Google-провайдера в Supabase, включите провайдер и сохраните.
9. В Supabase Authentication → URL Configuration укажите Site URL и разрешённый Redirect URL. Локально: `http://127.0.0.1:3000/`. После публикации добавьте точный HTTPS-адрес сайта.

При первом входе Google создаёт учётную запись через Supabase, при повторном возвращает пользователя в тот же аккаунт. Для публичного запуска настройте Audience Google соответствующим образом; могут потребоваться проверка бренда и страницы приложения.

Официальная инструкция: https://supabase.com/docs/guides/auth/social-login/auth-google

## 3. Открыть сайт

Требуется Node.js. В этой папке выполните `node serve.mjs`, затем откройте `http://127.0.0.1:3000/`. Двойной клик по HTML не подходит для Google OAuth.

Для публикации нужны только `index.html`, `app.js`, `config.js` на HTTPS-хостинге статических сайтов. Публикация ещё не выполнена. В бесплатных сервисах действуют ограничения, которые стоит проверить перед запуском.

## 4. Проверить до приглашения пользователей

- Войти Google-аккаунтом A, создать объявление с фото и точкой на карте.
- Выйти и войти снова: объявление должно оставаться в «Мои объявления».
- Войти аккаунтом B: опубликованное объявление видно, изменять его нельзя (включая прямые запросы к API).
- Аккаунтом A снять объявление с публикации: гость и B его не видят, A видит в своём кабинете.
- Проверить повторную загрузку организаций после временного сетевого сбоя.

Живой Google-вход, сохранение, хранилище и политики доступа ещё не проверены на вашем проекте. Проходимость и прибыль не прогнозируются. Помощник работает по правилам и настоящим данным OpenStreetMap, без платной языковой модели. Настоящие объявления должны добавлять владельцы — фиктивных предложений нет.
